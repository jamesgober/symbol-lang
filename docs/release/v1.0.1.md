# symbol-lang v1.0.1: lookup independent of nesting depth

**Patch.** v1.0.1 makes `SymbolTable::lookup` cost the same however deeply the
scopes are nested. The public API and its behaviour are unchanged, and every
1.0 guarantee still holds.

## Fixed

### Lookup was linear in the scope depth

The table kept one map per scope, and `lookup` searched them from the innermost
out. A name defined near the root and used at every level of a deep nest
therefore cost `O(depth)` per lookup and `O(depth^2)` over the whole walk.
Machine-generated code and deeply nested blocks can reach depths where that
shows.

The table now keeps a single map from each name to a stack of its live
bindings, innermost on top, and each scope records the names it defined.
`define` pushes onto the name's stack or replaces the top when the name is
already bound in the current scope; `exit_scope` pops exactly the names the
scope defined. `lookup` and `lookup_local` read the top of one stack, so each is
one map search over the names currently bound.

Shadowing, redefinition in the same scope, the value `define` returns, and the
root scope that can never be exited all behave as before. The existing property
tests, which check the table against an independent model over long random
operation sequences, pass unchanged.

In a debug build, looking an outer name up at each of 16,000 nested levels went
from about 1.6 s to a few milliseconds.

## Tests

`tests/deep_scopes.rs` compares that walk at 2,000 and 16,000 levels and fails if
the deeper one costs more than 30 times as much (depth-linear lookup costs about
64 times as much). It also unwinds 1,000 levels of shadowing and checks every
lookup on the way out.

## Upgrading

```toml
[dependencies]
symbol-lang = "1.0"
```

No code changes are needed.
