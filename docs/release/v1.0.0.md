# symbol-lang v1.0.0 — API freeze

**Stable.** v1.0.0 freezes the public API. The symbol table and name diagnostics
built in 0.2.0 are now under a Semantic Versioning promise: no breaking change
before `2.0`, additions only in minor releases, MSRV (Rust 1.85) rising only in a
minor. There are no functional API changes from `0.2.0`; this release is the
commitment.

## What is symbol-lang?

The name-resolution substrate of the `-lang` family: a lexically-scoped
[`SymbolTable`] mapping interned names to bindings, and ready-made diagnostics for a
name used but not defined, or defined twice. It is generic over the binding — the
language decides what a name resolves *to* — so one scope engine serves every
language. Names are [`intern-lang`] `Symbol`s; errors are [`diag-lang`]
diagnostics.

## The frozen surface

- **`SymbolTable<T>`** — `new`, `enter_scope` / `exit_scope` / `scoped`, `define`,
  `lookup` / `lookup_local`, `is_defined`, `depth`. A name resolves to the nearest
  enclosing binding; inner scopes shadow; the root is always present.
- **`unresolved_name` / `duplicate_definition`** — the two name-error diagnostics,
  the latter linking both sites.
- **Re-exports** — `Symbol` (intern-lang) and `Diagnostic` / `Span` (diag-lang).

The full reference, the SemVer promise, and what is deliberately left out (an
`ast-lang` dependency, a persistent scope tree, a built-in interner — all addable
later) are in [`docs/API.md`](https://github.com/jamesgober/symbol-lang/blob/main/docs/API.md).

## Guarantees

- **Correct lexical scoping.** `lookup` returns the nearest enclosing binding; an
  inner definition shadows an outer one while its scope is open and the outer is
  visible again after exit. Held by a property test against an independent reference
  model over long random operation sequences.
- **Total operations.** Looking up an unbound name is `None`, exiting the root is a
  defined no-op, and no sequence of calls panics — the chain is always non-empty.
- **Balanced scoping.** `scoped` enters and exits exactly one scope, so depth is
  unchanged across it.
- **Consistent diagnostics.** Every language reports unresolved names and duplicate
  definitions in the same documented, source-annotated form.
- **`no_std`** with `alloc`; `#![forbid(unsafe_code)]`; no `unwrap`/`expect`/`todo!`
  in shipping code.

## Breaking changes

**None.** Identical API to `0.2.0`. From here, breaking changes require `2.0`.
