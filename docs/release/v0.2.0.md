# symbol-lang v0.2.0 — Symbol table & name diagnostics

**The core, front-loaded.** v0.2.0 turns the scaffold into a working name-resolution
substrate: the lexically-scoped [`SymbolTable`] a resolver threads through a tree
walk, and the ready-made diagnostics for the two name errors every language
reports. This was the hard part of the roadmap, and the roadmap put it first.

## What is symbol-lang?

The first SEMA-tier crate: where a tree of syntax becomes a program with meaning.
It maps interned names to bindings across a chain of lexical scopes, and reports a
name used but not defined, or defined twice. It is generic over the binding — the
language decides what a name resolves *to* — and keys every scope on an
[`intern-lang`] `Symbol`.

## What's new in 0.2.0

### `SymbolTable` — the lexical scope chain

```rust
use symbol_lang::SymbolTable;
use intern_lang::Interner;

let mut names = Interner::new();
let x = names.intern("x");

let mut table: SymbolTable<i32> = SymbolTable::new();
table.define(x, 1);
table.enter_scope();
table.define(x, 2);                   // shadows the outer `x`
assert_eq!(table.lookup(x), Some(&2));
table.exit_scope();
assert_eq!(table.lookup(x), Some(&1)); // outer `x` is back
```

`enter_scope` / `exit_scope` (or `scoped`) bracket a block; `define` binds in the
current scope and hands back any binding it shadows there; `lookup` searches
outward to the nearest enclosing definition, `lookup_local` the current scope only.
There is always a root scope, so the table is usable immediately and the root can
never be exited.

### Name diagnostics

[`unresolved_name`] and [`duplicate_definition`] build the two universal name-error
[`diag-lang`] diagnostics — the second linking both the redefinition and the first
definition — so every language reports them the same, source-annotated way.

### Tested against a reference model

`tests/properties.rs` runs long random sequences of enter/exit/define/lookup
against an independent `Vec<BTreeMap>` model and checks they agree after every
operation; `tests/resolution.rs` resolves a tiny program end to end — binding,
shadowing, an out-of-scope use, a duplicate — and checks the diagnostics.
Benchmarks measure `define` and chained `lookup`.
